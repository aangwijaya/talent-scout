02 The cast

Who does what

Each role has one job and only the access that job needs.

Me, the human
Decides what to build and approves plans, mockups and contracts. Holds every secret, runs production and live-model steps, and merges every PR.
Lead agent · Claude Code
Works with me in the control plane. It grills the plan, mocks up screens, writes issues as fenced nodes, verifies every PR and turns findings into decisions for me. It never dispatches work.
Orchestrator · ops/run
Plain code, not an LLM, so no model decides the flow. It picks the next ready node, builds the sandbox, runs the gate, pushes and opens PRs with my login, and starts the review.
Client agent · Claude Code  |  Server agent · OpenCode
Claude Code builds the SvelteKit client and OpenCode builds the Go server. Each writes tests first, then the code, then a handoff.
Reviewer · the other agent  |  Verifier
A read-only session of the other agent reviews each PR. A verifier sub-agent then checks the review against the code and sabotages the tests.
The lead agent has no production access either. It prepares commands and SQL, dry-runs them on a test schema, and I run them.

05 The sandbox

Every agent runs
inside four walls

These limits are enforced by the orchestrator and by GitHub. Nothing depends on the agent behaving.

4 · Run limits$6 budget · 60 min · 3 attempts
3 · Its own identityGitHub token: issues only
No access to my gh login or SSH key. Git runs over HTTPS with the agent token, and GitHub refuses its pushes (403).
2 · A clean environmentallowlisted env vars
All other variables are dropped. It gets a separate Supabase project, LLM_MODE=fake and EMAIL_MODE=log.
1 · A fenced worktreeone per node
It may change only the paths in its fence. Writes outside are denied, except its handoff file.

07 After the merge

The loop closes
and gets smarter

01
Reconcile
ops/run --reconcile drops stale labels and removes merged worktrees. Blocked nodes become ready.
02
Contract sync
When the server contract moves, the orchestrator opens a sync PR on the client. contract.lock pins the server commit and file hashes.
03
Live gate
For prompt and model changes, I run three real CVs through real models with a capped key. The lead agent reads the log for cost, truncation and output.
04
Production steps
Migrations and data changes are prepared and dry-run on a test schema. I run them on production.
05
Learning loop
Each node writes lessons to docs/LESSONS.md. A lesson that repeats becomes a skill-update node, and a check or lint rule beats more text.
